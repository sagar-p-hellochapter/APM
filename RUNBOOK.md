# RUNBOOK — Chapter PM Assistant Portal

How to run, refresh, and maintain the portal.

## What "self-updating" means here
The portal is a static page with an **embedded data snapshot** (offline fallback) that also
**live-fetches `data/*.json`** when hosted. It does not invent fresh data on its own — the
data is regenerated by a **scheduled refresh** that re-pulls the HUB + Outlook and rebuilds
the page. So:

- **A downloaded copy of `index.html` never changes** — it's a point-in-time file.
- **A hosted page** (the claude.ai artifact, or a Netlify deploy) updates **each time the
  scheduled refresh runs and republishes/redeploys.**

## One-command rebuild (from the raw snapshots already on disk)
```bash
node skills/refresh.mjs --ref $(date +%F)
```
Runs every transform in order (aggregator → email-consolidator → daily-todo → payment-tracker
→ co-tracker → weekly-drafter → reminder-engine) and rebuilds `portal/index.html`.

## Full refresh (re-pull live data, then rebuild) — what the scheduler does
The live pull is done by the agent/Routine via MCP (scripts can't call MCP), then `refresh.mjs`:

1. **HUB** — `hub_list_projects` + `hub_get_project_overview` (all 7) → `data/raw/hub-snapshot.json`;
   `hub_get_project_tasks` (not-done, all 7) → `data/raw/tasks-snapshot.json`;
   `hub_get_change_order_costs` (5 CO projects) → `data/raw/co-snapshot.json`.
2. **Outlook** — `outlook_email_search` per project (street-address query) → `data/raw/emails-snapshot.json`.
3. `node skills/refresh.mjs --ref $(date +%F)`
4. **Republish** the artifact (same file path → same URL) and/or `netlify deploy`; then commit.

If a source is unauthorized at run time, keep its last snapshot (the page shows last-good data).

## Schedule (config/settings.json)
- **Nightly 11:00 PM ET** (`dailyResetTime`) — full operational refresh (tasks, payments,
  reminders, emails).
- **Friday 2:00 PM ET** (`weeklyUpdate`) — also re-synthesize the weekly client-update drafts.

These run as **Claude Code Routines** (scheduled triggers) that fire the refresh + republish.
Cron is stored in UTC: nightly `0 3 * * *`, Friday `0 18 * * 5` (EDT; shifts one hour in EST).

## Production (always-on, independent of any chat session)
For a page that updates 24/7 without this session alive, deploy `portal/` + `data/` to **Netlify**
and run the refresh as a **scheduled Netlify function** (or GitHub Actions cron) holding your
HUB + Microsoft Graph credentials. The HUB uses interactive OAuth, so unattended refresh needs
a token you provision. This is the only fully-hands-off option.

## Config you own
- `config/settings.json` — reset times, urgency windows, health rules, **email signature**,
  self-send allowlist.
- `config/subs.json` — real subcontractors + payment schedules (currently example data).

## Safety
Email is **draft-only** for anything external; the only address the system may ever auto-send
to is in `settings.email.selfSendAllowlist`. No writes back to the HUB.
